## 正常链路

1. 用户无需登录下载 `website/assets/creator-guide.zip`，交给其他 AI 制作单个 `.nmgpack`。新制作的 `manifest.id` 固定为 `creator.template`，不要求先创建作品或复制编号。
2. 手机号登录默认保持 30 天，无需昵称或手机号绑定入口。新作品只填写作品名、简短单行介绍、选择文件及明确授权，校验并确认真实预览后送审；更新从自己的作品选择已有作品再上传新版。
3. 服务端依据已登录账号和新建 / 更新目标校验归属，将通用模板安全绑定真实作品。兼容既有真实 ID 源包，但必须匹配当前作者的对应作品，不能由客户端自报身份绕过归属检查。
4. 程序检查 ZIP 布局、重复文件、CRC、解压预算、严格 manifest、PNG 格式与解码预算。只接受根目录 manifest 和已声明 PNG，不接收脚本、程序、工程或作者的验证工具；校验错误返回安全字段定位，不进入自动批准。
5. PNG 规范化去除非显示所需附加块，保留严格校验的 RGB 透明色数据；有界解压并私有保存规范化版本。原上传摘要仅供追溯，预览、审核和后续交付绑定同一规范化版本。
6. 作者明确授权平台免费存储、审核和分发作品，并另行明确授权将图片和公开文字交给 AI 审核。服务端将当前免费授权、可选本人抖音号及公开文字冻结到具体投稿快照及审计，不仅依赖页面勾选。历史收费授权不能自动替代本次免费授权。
7. 服务端复核私有源包与摘要，用平台动画规则生成真实帧联系图，连同封面、图层素材及冻结的公开文字送审。AI 只审核图片与公开文字，不执行源包，不承担恶意代码检测。
8. 明确通过则自动审核并上架；明确内容违规则拒绝并给出中文说明。配置缺失、服务错误、预算耗尽、版权疑问或不确定结果保留待处理，后台可作例外复核，不能默认放行。
9. 官方与社区作品统一发现、预览。基础木鱼随客户端直接免费下载；扩展形象凭群码或作者码免费领取，每批最多 10 个，权限不消耗，代码每 72 小时轮换。有效新作贡献按 `min(3*N,10)` 增加作者码单批权限，模板、合成验收样例和官方复制内容不计贡献。新签发包永久离线导入，服务器重下载期为首次成功签发后 7 天，不再要求 24 小时内首次导入。新流程不付款、不分成；历史订单独立保留履行，客户端不在线检查领取码或支付。

## 程序安全门禁

| 检查 | 上限或规则 |
| --- | --- |
| ZIP | 普通单卷 stored / deflate；拒绝 ZIP64、加密、分卷、自解压、数据描述符、注释、尾随数据、路径穿越、链接、隐藏文件与重复文件 |
| 体积 | 压缩 8 MiB，展开 12 MiB，manifest 64 KiB |
| 文件 | 根目录最多 8 个，只有 `manifest.json` 与 1 至 7 张实际引用的 PNG |
| PNG | 静态、非交错、8 位 RGB/RGBA；宽高各不超过 2048，解码内存合计不超过 64 MiB；不接受 APNG、索引色、灰度或 16 位 |
| manifest | 严格字段白名单、有限数值、固定画布、1 至 6 层、每层 1 至 8 个有序关键帧、图片引用完整 |
| Schema 1 | 图层 frame 还需 y 不小于 0、y + height 不大于 170；不因通用 AI 提示遗漏而放宽 |
| 身份 | 通用 ID 只由服务端绑定；既有真实 ID 必须匹配账号与目标作品 |

安全防线是程序校验及资源限制，不是让 AI 承诺“无病毒”。后台例外复核也不能绕过安全门禁。PNG 规范化不是安全认证，动画抽样及图层审查不能证明穷尽每一帧或证明版权。

## AI 输入与决定边界

- 只发送缩略素材、平台渲染帧和作品名、介绍、署名等公开文字；技术摘要、数值 manifest 与版本绑定由服务端处理，不把账号、手机号、验证码、会话、支付或存储密钥交给模型。
- 图片及文字中的指令一律是不可信数据，模型无工具调用权限，不请求投稿携带的 URL，不执行代码。
- 模型结构化响应必须经服务端严格校验；截断、空内容、工具调用、不符合结构或未知结论不能批准。
- 结果绑定 reviewId、versionId、源包摘要及 revision；上架事务再次检查作者状态、当前授权、最新投稿与下架意图。
- 新版本待处理不覆盖已上架旧版；发布后才切换。已领取批次和历史已付款订单继续使用当时的固定审核版本，不按最新版本重新交付。普通下架不撤销有效既有领取；安全停发和作者暂停依 PRD 阻断分发，不能因更新自动恢复。
- 无 AI 授权的历史投稿不进入自动队列；队列选择、抢占、调用前及决定事务都检查授权。可在既有投稿界面补充当前免费与 AI 授权并保留源版本；不能由旧条款推定当前授权，也不自动补计历史作者贡献。
- 例外复核、投诉、暂停及下架保留人工入口；例外决定如实记录人工身份，不伪装成 AI 结果。明确通过的正常链路不要求逐件人工审批。

## 配置与恢复要求

仅由主任务在批准的生产接入中配置；以下是服务端配置示例，不表示已启用，不放进官网、客户端、Git 或普通日志：

```dotenv
GONGDE_CREATOR_AUTO_REVIEW_ENABLED=true
GONGDE_CREATOR_REVIEW_API_KEY_FILE=/run/secrets/gongde_creator_review_api_key
GONGDE_CREATOR_REVIEW_DAILY_LIMIT=20
```

生产使用独立的文件密钥入口，不借用其他项目凭据。具体模型标识、视觉能力、端点及配置结果由主任务核对并记录，不能以示例、密钥文件路径或页面文案推定可用。缺少配置时投稿保留待处理，不自动上架；不要为恢复审核重新开启新收费。

现有审核设计预算为单次请求 25 秒、输出上限 1024 tokens、响应体上限 64 KiB、单进程同时一个请求；实际生效需运行回执。未启用显示 `disabled`，启用但配置缺失显示 `unavailable`，`automatic` 仅是能力状态，不能替代某件作品的通过记录。

- review 保留 `PENDING` / `APPROVED` / `REJECTED`，在 `checks_json` 保存自动阶段、次数及有界证据，不另建审核真相库。
- `running` 使用最长 60 秒租约，私有源包复核后续租再请求模型；失效租约的旧结果不能发布。
- 临时错误最多三次尝试，间隔 1 分钟、5 分钟；从数据库待审核记录恢复，不依赖网页持续打开。
- `needs_review` 停止自动重试，留给例外复核；不为了减少人工而自动批准未知内容。
- 自动审核 actor 为 `automation:deepseek`，人工例外另记。送审页面有限轮询约 90 秒并保留刷新结果，关闭页面不撤销投稿。
