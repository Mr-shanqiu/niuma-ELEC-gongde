## 推荐流程

1. 无需登录，打开官网制作指南并下载 `creator-guide.zip`。把整个指南包交给你选用的 AI 或制作工具，让它阅读 `README.txt` 和 `AI-PROMPT.txt`，描述你想做的形象和动作。
2. 让工具交付一个真实的普通 ZIP 格式 `.nmgpack`。通用模板的 `manifest.id` 固定为 `creator.template`，无需账号信息或作品编号；不要夹带制作脚本、程序或工程。
3. 使用手机号登录创作者工作台，默认保持登录 30 天，无需设置昵称，不展示手机号绑定入口。
4. 选择“发布新作品”：填写 1 至 20 个 Unicode 码点的作品名和 1 至 40 个码点的单行介绍，选择文件；标签选填，最多 3 个、每个 1 至 8 个码点。本人抖音号选填，不填写也不影响投稿或推广权限。分别主动确认素材权利、免费分发声明和 AI 图片与公开文字审核授权；校验通过、检查真实预览后再送审。平台在已登录用户上传时安全绑定真实作品，不要求用户修改 JSON 或编号。
5. 更新时从“我的作品”选择已有作品，再上传新版文件，不要重复发布成新作品。已有带真实作品 ID 的源包仍兼容，但仅限自己的对应作品；不能通过修改 ID 越权投稿。
6. 程序安全门禁通过后，AI 只审核图片和公开文字。明确通过时自动审核上架；明确违规给出拒绝原因；错误、不确定或配置未就绪保留待处理，后台可作例外复核。只有通过、公开且具备当前免费分发授权的版本才可领取；人工复核也不能绕过程序安全门禁。

## 指南 ZIP 与上传源包不是同一个文件

`creator-guide.zip` 的构建说明定义了五个文件：

| 文件 | 用途 |
| --- | --- |
| `README.txt` | 制作、上传及更新步骤 |
| `AI-PROMPT.txt` | 给其他 AI 的制作要求和格式说明 |
| `manifest.json`、`sample.png` | 可替换素材的最小 Schema 1 模板 |
| `example.nmgpack` | 已封装的示例，可用于上传和预览，不是已审核作品 |

最终只上传 `.nmgpack`，不要上传整个指南 ZIP。最小源包根目录为：

```text
manifest.json
sample.png
```

可以替换图片或增加已引用图层图片，但须同步更新 `preview` 和图层 `image`。源包不含 `license`、签名、订单、价格、授权码、`review.json`、README、脚本或其他交付字段；签名与交付授权由平台处理。待审核源包不直接导入客户端。

网页介绍单独填写，不要把介绍、联系方式、手机号或价格写入 manifest。本人抖音号使用网页字段 `creatorDouyinNumber`，不添加到严格白名单 manifest；最多 32 位 ASCII 字母、数字、下划线、短横线或点，不填写链接、昵称或分享口令。更新可以修改或清空，审核通过后才随新快照公开。包内 `author` 是公开素材署名，不是登录昵称；手机号不要用作公开署名。

## 初学者：保留 Schema 1

先保持模板的一图层、三个轻微动作关键帧，只替换作品文字和图片，再看工作台实际预览。根字段、图层和关键帧均为严格白名单。

| 字段 | 要求 |
| --- | --- |
| `schema_version` | 数字 `1` |
| `id` | 新制作固定 `creator.template`；平台上传时绑定真实作品。既有真实 ID 源包仅限自己的对应作品更新，不展示复杂 ID 格式作为新用户步骤 |
| `version` | 1 至 32 位 ASCII，匹配 `^[a-zA-Z0-9][a-zA-Z0-9._-]*$` |
| `name_zh`、`name_en`、`author` | 各 1 至 80 字，不能全为空白或含控制字符；署名会公开 |
| `publisher`、`review_id` | 固定为 `community`、`pending`，不能自行声明已审核 |
| 画布 | `canvas_width=240`、`canvas_height=250`、`plus_y=174` |
| `preview` | 根目录 PNG 文件名，不是 URL |
| `layers` | 1 至 6 层；每层仅 `image`、`frame`、`anchor`、`keyframes`，不能加图层 `id` |
| `frame` | `[x,y,width,height]`；x 为 -240 至 480，y 为 -250 至 480，宽高为 1 至 480。Schema 1 **另要求 y 不小于 0，y + height 不大于 170** |
| `anchor` | `[x,y]`，各在 0 至 1 |
| `keyframes` | 每层 1 至 8 帧，仅 `t`、`x`、`y`、`rotation`、`scale`、`alpha` |
| 关键帧数值 | 全部有限；t 为 0 至 1，首帧为 0，其后经单精度转换仍严格递增；x/y 为 -480 至 480，rotation 为 -180 至 180，scale 为 0.1 至 4，alpha 为 0 至 1 |

制作时按 ZIP 说明推荐末帧 `t=1`，静态形象也写两个相同起止状态；这是制作建议，不把校验器允许的单帧误写为非法。

进阶 Schema 3 在每层增加 `interpolation`（`linear` 或 `smoothstep`），每个关键帧增加 `scale_y`（0.1 至 4）。Schema 1 不接受这些字段；不熟悉时继续用 Schema 1。格式通过不等于内容审核、素材权利确认或双端运行验收通过。

## 容器与图像预算

| 项目 | 限制 |
| --- | --- |
| ZIP | 普通单卷，仅 stored 或 deflate；不用 ZIP64、加密、分卷、自解压、数据描述符、全局注释或尾随数据 |
| 根目录文件 | `manifest.json` 加 1 至 7 张已引用 PNG，最多 8 个文件；不允许子目录、链接、重复文件、隐藏文件或未声明素材 |
| 体积 | 压缩包最多 8 MiB，展开后最多 12 MiB，manifest 最多 64 KiB |
| manifest | UTF-8 JSON，不带注释或额外字段 |
| PNG 文件名 | `^[a-z0-9][a-z0-9_-]{0,59}\.png$`，根目录小写 ASCII 名称 |
| PNG 格式 | 静态、非交错、8 位 RGB/RGBA；不用 APNG、灰度、索引色、16 位或不支持的块 |
| 图像预算 | 宽高各不超过 2048 像素；全部图像解码内存不超过 64 MiB |

每张 PNG 必须被 `preview` 或图层 `image` 引用，所有引用必须存在；预览与图层可以共用图片。不放 `.DS_Store`、`__MACOSX`、代码、HTML、SVG、视频、字体、JPEG 或 GIF。仅更改扩展名不等于正确封装。

## 常见错误与修复

| 现象 | 修复 |
| --- | --- |
| ID 不匹配 | 新制作让 AI 恢复 `creator.template` 后重新封装；既有真实 ID 源包从自己的对应作品更新入口上传，不猜编号、不使用他人 ID |
| `publisher` / `review_id` 错误 | 保留 `community` / `pending`，删除从交付包复制的授权、签名、价格等字段 |
| manifest 字段无效 | 删除自定义字段与图层 `id`，不要在 Schema 1 混入 Schema 3 字段 |
| 图片引用不匹配 | 图片改名后同步 `preview` 和所有 `image`，清除未引用图片、隐藏文件与目录 |
| PNG 不支持 | 重新导出静态、非交错、8 位 RGB/RGBA PNG |
| Schema 1 保留区域越界 | 每层 y 不小于 0、y + height 不大于 170；不要只依赖 AI 说明中的通用 frame 范围 |
| ZIP 无法解析 | 用普通 ZIP 重新封装，所有文件直接位于根目录，不使用流式数据描述符等不支持格式 |
| 程序校验失败 | 按安全字段定位修复再上传；后台例外复核不能绕过安全门禁 |
| AI 审核待处理 | 配置、服务、预算或判断可能未就绪；查看工作台结果，待处理不是已通过或已上架 |
