版本：沟通稿 v2

状态：方案设计，不是 UI 重构完成或发布证明。功能代码按新规则修改，本轮不运行验收、不使用桌面控制；本方案经用户沟通确认后才实施新界面。

## 1. 官网只承担三个任务

1. 让第一次来的电脑用户迅速理解桌面木鱼，并免费拿到客户端。
2. 让想换形象的用户在首页找到、预览、选择喜欢的形象。
3. 让用户自行选择付费省事，或进抖音粉丝群拿码免费领取，再保存文件。

不再把官网做成共创平台、商城账户中心或长篇产品说明书。以下是从任务和操作顺序出发的新结构，不以保留现有版式为前提。

## 2. 已冻结的业务边界

| 项目 | 规则 |
| --- | --- |
| 客户端与基础木鱼 | 始终直接免费，无需登录、领码、关注或付款 |
| 扩展形象 | 每个 1 元，每批最多 10 个不同形象，无套餐、折扣或封顶价 |
| 付费下载 | 仅购买本次下载；以后重新下载相同形象也重新付费，或使用有效群码 |
| 已保存的文件 | 长期离线使用，重新导入本地文件不收费 |
| 群码 | GD 加六位数字，大小写均可，每三天更新，不扣共享额度 |
| 图库 | 留在首页，不迁到独立页面 |
| 普通用户身份 | 不要求账号、手机号、昵称或关注验证 |
| 共创和历史功能 | 本轮不展示投稿、作者推广、历史订单、找回和旧权益入口 |
| 目标设备 | 电脑端，不扩展手机端体验 |

## 3. 两条核心用户旅程

### 3.1 基础体验：无需决策就能开始

进入首页 → 看一句产品介绍和木鱼体验 → 点击免费下载 → 安装 → 使用基础木鱼。

首页不能先要求用户挑形象、看付款规则、扫码或进群。扩展购买失败、群码服务不可用都不能阻止基础客户端下载。

### 3.2 扩展下载：先选喜欢的，再决定取得方式

进入首页图库 → 鼠标悬停看动作 → 选择 1 至 10 个 → 选择付款或群码 → 下载一个批次文件 → 保存并导入。

付费分支：确认所选形象及 N 元总价 → 主动选择支付渠道并发起付款 → 确认到账 → 准备文件 → 下载。

群码分支：已有群码直接输入；没有码则展开抖音码和进群说明 → 拿到当期群码 → 回到原选择继续领取 → 下载。

切换分支不清空选择，用户不必重新找包。两条分支共用同一选择清单和交付体验，不把免费路线做成另一套产品。

## 5. 首屏的具体设计

主标题建议：“你忙你的，它替你攒功德。”

介绍建议：“打字、点鼠标，桌面木鱼就动一下。让忙碌多一点小快乐。”

主按钮：“免费下载木鱼”。次级文字动作：“挑选其他形象”。辅助说明：“支持 Mac / Windows，无需登录。”

下载动作优先提供当前系统的正式客户端，保留轻量的其他系统选择。不新建下载权限弹窗，不要求进群。已有安装说明在下载位置可找到，不占据主介绍。

木鱼完整显示，敲棒动作也不能被容器裁切。体验区域只演示用户主动点击产生的动作，不暗示网页已经获得系统全局计数能力。演示数字是体验值，不是客户端实际功德或产品用户数。

首屏压缩到电脑窗口中合理的高度，让用户能自然看到下方图库标题和首排预览，不做占满屏幕的大留白。

## 6. 首页图库的具体设计

标题建议：“换个小伙伴，也换个心情。”

规则只用一行：“扩展形象每个 1 元，也可凭粉丝群领取码免费下载。”

| 卡片元素 | 规定 |
| --- | --- |
| 预览 | 最大视觉区域，保持原图比例与完整动作范围 |
| 动作 | 悬停播放，移开静止；不需要播放按钮 |
| 名称 | 清楚的一行，太长时截断并可查看完整文字 |
| 介绍 | 短短的一句话，不出现格式或审核说明 |
| 价格 | 每张扩展卡显示 1 元，不用优惠标签 |
| 编号 | 次要位置，方便识别和分享，不抢名称的位置 |
| 选择 | 独立明确的“选择／已选择”及状态，不将悬停等同选中 |

基础木鱼由首屏免费入口承接，不混入收费选择。图库使用当前允许分发的在架形象，不在前端硬编码作品数量或复活已下架形象。

搜索与编号查找合成一条轻量工具栏，输入名称或编号即可找包。默认没有高级筛选、作者筛选或官方／社区切换。无结果时保留输入，提供清除动作。

已加载预览再次滚入视野时复用资源，不能整卡突然恢复成“正在加载真实预览”。只给尚未就绪的卡片局部加载反馈。无真实预览时明确不可用，不能用模拟动作冒充真实预览。

## 7. 选择栏

至少选择一个形象时才出现底部选择栏，页面末尾预留空间，不能挡住最后一排作品或帮助内容。

```text
已选 3 / 10 个     查看选择     清空
总价 3 元         [支付 3 元下载]     [用群码免费下载]
付款仅用于本次下载，请保存文件。
```

两个路线按钮都要显眼，免费路线不能藏成不起眼的文字，也不强制默认走群码。付款按钮明确总价，群码按钮明确免费，不使用含糊的“立即领取”。

“查看选择”在当前页面列出名称并允许移除，不新建购物车页。移除后数量与金额立即同步，最后一个移除后选择栏消失。

达到 10 个时提示：“每批最多 10 个，请先取消一个再选择。”原有选择不能被清空。

## 8. 下载侧面板

建议用一个统一的首页侧面板承载两条路线及交付。用户仍知道自己在首页，不必经历独立商城、购物车和账户中心。

侧面板是待确认的 UI 提案。功能修改阶段可以沿用原领取页和付款页接线，不因为本稿提前实施新面板。

### 8.1 共用部分

顶部显示“下载所选形象”，提供明确关闭动作。内容包含当前选择简表及数量，在面板内可切换“付费下载”和“群码免费”。切换不清空选择，不自动发起新的支付。

### 8.2 付款部分

展示“N 个形象 × 1 元 = N 元”，然后是必要说明、实际可用渠道和付款按钮。

付款前必须看到：

> 本次付款仅用于本次下载。请保存文件，保存后可以长期离线使用。以后在官网重新下载，即使是相同形象，也需要再次付款，或使用有效的群领取码。

用户主动点击后才创建交易。进入面板不能自动创建收款单或打开支付页。没有可用支付渠道时明确提示，允许切换群码或回到基础免费下载，不能用不可点击的白色按钮伪装为正常可用。

微信展示实际付款二维码；支付宝使用实际支付链接。交易截止时间来自服务端，不能用假倒计时催促。关闭面板不等于已取消真实交易，付款进行中需要明确提示。

刷新当前未完成付款可以恢复当前交易状态，但不能新建收费交易。交付完成后不保留用户历史订单入口，也不把已完成交易当成下次免费凭证。

### 8.3 群码部分

先给输入框和“免费下载所选形象”按钮。输入提示：“例如 GD565596，大小写均可。”保留前导零，不要求用户选择码类型。

下方是“没有领取码？去抖音粉丝群领取”。按需展开用户提供的抖音码、开发者抖音号和简短说明：“进入粉丝群查看当前领取码，每三天更新一次。”

官网不能展示当前有效群码本身，也不能声称验证了关注关系。二维码使用开发者实际提供的素材，不生成一个看似真实却不可识别的装饰码。

错误提示须区别不正确、已过期和服务暂时不可用。所选形象保持不变。不显示余额、扣减额度或剩余兑换次数。

### 8.4 文件交付部分

通过付款确认或群码验证后，同一面板展示文件准备状态，不让用户重新找下载入口。

| 状态 | 文字及操作 |
| --- | --- |
| 正在核对付款 | 正在确认付款结果，请稍候；不能仅凭前端返回显示已付款 |
| 正在准备 | 正在准备 N 个形象的下载文件；不显示虚假百分比 |
| 文件就绪 | 文件已准备好；主按钮“下载 N 个形象” |
| 准备失败 | 说明失败，当前已付款交易显示“重新准备”，不显示“重新付款” |
| 已触发下载 | 已发起下载，请查看浏览器下载列表并保存文件 |

文件按钮下提示：“保存到本机，再在客户端选择更换形象并导入。保存的文件可长期离线使用。”

浏览器触发下载不能当成文件已经保存，更不能声称用户已经导入成功。不要用大弹窗再次要求关注或分享。

## 9. 页面状态与异常

| 场景 | 反馈 | 保持的状态 |
| --- | --- | --- |
| 首次到访 | 免费木鱼清楚可得，图库在同页 | 不强制弹窗或登录 |
| 部分预览加载慢 | 卡片局部反馈，其他作品能继续看 | 已加载图与选择 |
| 图库没有结果 | 清楚无结果，可清除查询 | 查询文字 |
| 未选扩展形象 | 不展示空的付款面板 | 基础免费下载仍可用 |
| 达到 10 个上限 | 明确上限与取消方式 | 原有选择 |
| 某作品已下架或版本变化 | 指明作品并允许移除或重新确认 | 其他有效选择，不自动替换版本 |
| 码错误或过期 | 可重新输入或查看取码说明 | 所选形象 |
| 创建付款失败 | 明确失败及当前交易状态 | 不悄悄换一个交易重复提交 |
| 已付款准备失败 | 重试本次交付，不再收费 | 当前交易锁定版本 |
| 再次到访发起下载 | 按新的选择和总价选择付款或群码 | 无历史免费重下入口 |

预览缓存与形象文件下载权益是两件事。缓存能让图库更快，但不能被解释为购买后永久免费重新下载。

## 11. 视觉与信息密度

方向是温暖、轻松、有木质气质，而不是电商促销页。使用奶油底、暖橙主操作、深色正文，标题有适度性格，表单和操作文字以可读为先。

图库的主角是形象，不是大标签、价格卡或技术说明。不要叠加多块宣传、重复的规则面板、冗长介绍和强制弹窗。首次到访不看到关于后台流程的任何解释。

按钮不能出现浅底配白字而难以辨认的状态；忙碌、禁用与可点击要明确区分。所有主要操作支持键盘焦点，错误提示与对应表单就近出现，不通过页面跳动表达登录或领取结果。

## 12. 使用帮助与开发者信息

页面下方使用三步图示：下载客户端 → 选择扩展形象并下载文件 → 在客户端导入。旁边注明：“只用基础木鱼？安装后直接使用，无需后两步。”

Mac 和 Windows 权限说明分别链接到对应帮助页，不把系统权限说明塞进每个下载步骤。客户端保持现有关于、自启动、更换形象、功德日历和退出菜单，本次 UI 重构不改客户端。

开发者抖音信息在页下部和群码路线中可见，首次基础免费下载不被扫码要求拦截。GitHub 只作为页脚次要源码入口，必要署名和许可信息照常保留。

## 13. 供沟通确认的决定

| 决定 | 本方案建议 |
| --- | --- |
| 首页顺序 | 免费体验首屏 → 同页图库 → 简短帮助与开发者信息 |
| 选包反馈 | 有选择才出现底部栏，数量、总价和两条路线一起显示 |
| 付款／群码承载 | 同一个首页侧面板，不新增商城和购物车页 |

| 图库密度 | 四列为主，大预览，名称、一句介绍、1 元、选择；编号次要 |
| 规则披露 | 首页只一行，付款前完整说明再次下载收费 |

以上等待用户沟通确认。价格、基础免费、图库留首页和无历史订单是既定规则，不作为 UI 讨论时重新加入复杂机制的入口。

## 14. 实施顺序及当前边界

先收口已批准的功能代码修改，本轮不运行验收、不占用 zhijia 的桌面控制技能。随后完成本 UI 方案沟通；确认后才重构界面。

界面重构只改官网体验，不借机修改客户端、签名、包格式、账户体系或支付业务规则。部署、验收状态独立记录，不能因为新方案写好就称产品已上线。

付款接口当前报告的进程内防重复创建及缓存上限是独立的服务端已知缺口，不通过增加历史订单页面掩盖，也不靠 UI 新增按钮解决。它不妨碍 UI 方案讨论，但正式开放收费前需要另行收口。

## 功能基线冻结后的设计补充（2026-10-15）

### 页面组织与信息优先级

桌面首页只承担四项任务，按顺序呈现：理解产品、直接下载免费客户端、同页挑选扩展形象、选择付费或官方群码领取。图库不跳转到独立页面。导航只保留「挑选形象」「下载客户端」「使用帮助」；开发者抖音和 GitHub 放在页脚次要区域，不与主要下载行动竞争。暂停期间不呈现共创入口、投稿引导、作者权益码或分成信息。

首屏主标题说明「打字、点鼠标，桌面木鱼动一下，功德 +1」。主按钮为「免费下载客户端」，辅助行动为「挑选更多形象」。按钮旁固定写「基础木鱼永久免费，无需登录或领取码」。不要把进入抖音群设为免费下载客户端的前置步骤。Mac 与 Windows 下载选择呈现真实平台名称和现行版本，不能只依赖自动识别；帮助链接分别指向两套既有权限说明。

首页中部为形象图库。每张卡片显示名称、一句短介绍和「¥1 / 个」，通用编号作为次要信息。悬停播放动作，不要求先点播放按钮；点击「选这个」加入本批次。重复点击取消选择。木鱼展示为「客户端内置免费」，不计入付费批次，也不挤占扩展形象名额。不要显示官方/社区分类、已购买或永久权益标签。

图库工具仅保留按名称或通用编号查找，以及必要的排序。空结果要说明「没有找到这个形象」，提供清除搜索；加载失败不要伪装为空结果。已成功加载的预览保持显示，滚动离开不重置成加载占位。预览尚未就绪时不允许以旧修订号提交订单。

有选择时显示固定批次栏：「已选 N/10 个」「合计 ¥N」「继续获取」。未选择时不显示遮挡内容的空批次栏。到第 10 个时保留现有选择，并在其他卡片旁提示「本批最多 10 个，先取消一个再添加」；不产生第 11 个选择、不另开套餐或显示封顶价。

1. 首屏理解产品和本地离线运行属性。
2. 点击「免费下载客户端」，选择 Mac 或 Windows。

### 扩展形象的统一获取面板

选定批次后打开同一获取面板，始终展示名称清单、数量和总价，并允许返回修改选择。面板同时呈现「直接付款下载」和「我有官方群领取码」两个清晰选项，不把第二条路线藏在错误提示或帮助文章里。简短解释为「每个形象 ¥1；也可在开发者抖音粉丝群领取当期免费码」。只承诺验证领取码，不承诺核验用户是否关注抖音。

付费路线：选择微信或支付宝 → 创建本次交易 → 展示付款指引 → 明确显示确认付款状态 → 文件备好后显示「下载本批次文件」。N 个形象合计 N 元，无套餐优惠。每一次重新发起下载均是新交易，即使形象相同。不得把本次交易成功宣传为以后免费或长期购买权益。

群码路线：输入 GD 加六位数字 → 点击「验证并免费领取」 → 验证成功后下载本批次文件。输入框接受大小写，展示时统一大写；不要求用户手动转换大小写。解释为「官方群码每三天更新，请到群置顶获取当前码」。它是当期领取权限，不是使用一次就减少的共享余额，不显示剩余额度、扣减次数或作者贡献额度。

两条路线最终都交付一个可整批导入的文件。不要让用户按形象重复下载或重复导入。文件导入后由纯本地客户端使用，不设首次导入倒计时，不要求客户端联网检查付款或群码。

### 状态、失败和关闭的交互合同

- 创建交易中：立即显示明确进度，防止重复点击创建；未知结果不能提示「未创建订单」并自动新建。
- 参数或预览已变化：只有服务明确证实交易尚未创建时，才能返回调整选择后重新发起；不能根据 HTTP 状态码自行推断。
- 待付款：显示本次金额和付款渠道。用户可返回已创建的本次交易，不生成第二笔交易。
- 确认付款中：文字为「正在确认付款，请稍候」，不要提前显示成功，也不让用户再付一次。
- 文件准备中：显示「正在准备本批次文件」。失败时保留当前交付状态并提供重试，不把已付款的当前交易清掉。
- 下载启动后：只提示「已开始下载，请查看浏览器下载列表」，不能断言文件已保存。
- 用户确认文件保存后：点击「文件已保存，完成本次下载」，清除当前交付状态，回到图库。不要增加历史订单、历史领取记录或恢复旧流程入口。
- 群码无效或过期：保留选择和输入位置，说明去群置顶取新码；提供切换付费路线，不诱导用户认为已经付费。
- 付款渠道不可用：只禁用相应渠道并说明原因。若全部不可用，保留群码路线；不可展示可点击却必然失败的支付按钮。

### 11. 客户端下载与安装帮助

客户端下载页只有当前 Mac 和 Windows 两个平台卡片，版本 0.9.3 与“内置木鱼免费”说明可见。可以按浏览器提示平台高亮推荐项，但不自动下载，也不隐去另一平台。

在 Linux 或无法识别系统的浏览器上，明确“目前提供 Mac 和 Windows 客户端，请选择目标电脑的平台”，不把 Linux 识别成 Windows，不提供伪造的 Linux 文件。

正常下载按钮保留已有同源固定下载入口与服务端文件名，不改成整包 fetch/blob，不影响下载断点、浏览器下载面板或现有文件摘要。

安装说明分 Mac 与 Windows 两个折叠部分，默认展开所选平台。系统安全提示按现有真实签名状态解释，链接到对应平台帮助；不把未经公证或未签名安装包描述成无提示，不指导全局关闭安全防护。

历史安装版本、内部摘要和发布回执不出现在普通下载页主区域。源码链接放页尾“项目说明”下的次要入口“查看源码”，字号可小于导航但仍可辨识；不能借弱化展示隐藏许可或隐私说明。

### 12. 管理端界面原则

本轮管理端功能已适配最新规则，官网 UI 重构不再扩展管理业务。管理首页以价格、每批上限、支付配置与群码状态为概览；源码摘要、原始底账和历史安装版本留在次级详情中。

“当前安装包”默认每个平台只呈现当前正式版本。上传材料与切换正式发布是两件事，按钮及成功提示必须区分。禁止仅因为上传成功就写“官网已更新”。

官方群码页面优先展示当前码、有效期、状态、复制码和复制群公告。轮换、暂停等生产写操作保持既有确认，不为了减少按钮把危险操作变成无确认点击。

### 13. 可用性与无障碍细节

| 场景 | 设计要求 |
| --- | --- |
| 键盘操作 | 所有选择、搜索、关闭弹层和提交按钮可聚焦；焦点轮廓清晰 |
| 弹层 | 打开时聚焦适当输入；关闭回到触发按钮；关闭不清空批次；提交中的状态不能被关闭动作当作取消成功 |
| 表单错误 | 具体错误显示在对应输入旁，不能只用顶部瞬间消失提示 |
| 状态反馈 | 文字与图形同时表达，不只用橙色、绿色或透明度区分 |
| 价格 | 合计金额固定小数格式，标题与按钮金额一致，不隐藏数量 |
| 禁用按钮 | 灰底深字、仍看得见按钮文案；不能白底白字或看似可用但无响应 |
| 长内容 | 名称必要时两行；完整名称可通过详情查看，不牺牲按钮空间 |
| 断网 | 保留选择和可见预览；出现网络恢复后的重试，不伪造成功 |
| 隐私 | 不把群码、买方凭据、签名 URL 或登录信息送入埋点和截图报告 |

### 15. 上线前 UI 判定清单

- 首屏没有账号、共创、历史订单、分成或旧免费规则入口。
- 免费基础客户端入口不被群码、抖音弹层或付款拦截。
- 首页图库不分散到独立页面；只展示真实在架内容。
- 付费与群码同一批次、同一数量上限；两条路线可发现且无诱导默认选择。
- 形象木棒和完整动作不裁切，悬停能播放，已加载预览不因滚动闪回骨架。
- 当前付款刷新和失败重试不生成新付费要求；实际是否付款仍由服务端确认。
- 交付页不虚构文件已保存、假进度或关注已验证。
- 首次安装与导入指引明确，批次仍是一个文件。
- 桌面窄视口及显示缩放下，选择栏、按钮、文字和弹层无覆盖。
- 管理端不重新出现共创入口和大量旧安装版本主列表。

本清单是后续界面验收口径，不是本次已经通过的结果。

## 桌面官网 UI / UX 方案 V4：先体验，再选择（2026-10-15）

### 1. 本次要解决的真实问题

现有首页把产品介绍、功能特点、隐私解释、再次下载、反馈、开发者、离线说明逐段铺开，用户重复阅读相似信息。图库展示作者、编号和分发规则，结算页用下拉框隐藏另一条领取路线，交付页重复出现三步说明和两步说明。页面说明量大于用户完成任务所需要的量。

新网站只回答三个问题：这是做什么的？怎样免费体验？怎样换自己喜欢的形象？首页以免费基础款体验为第一目标；扩展形象的付费与群码路线同时清楚展示。不给访问者增加注册、关注验证或创作者身份。

### 6. 两条用户旅程

#### 6.1 第一次来，先免费体验

打开首页，试玩木鱼，点击本机平台免费下载，浏览器保存安装包，页面呈现简短安装步骤。用户安装后即可使用基础木鱼。流程不经过结算、验证码、群码或抖音页面。

下载提示显示“01 客户端：只需安装一次”。Mac 与 Windows 帮助链接分别进入正确平台的已有解释页。页面不自动推断安装成功，也不弹出不准确的“已安装”通知。

#### 6.2 已选形象，付费下载

首页选择 N 个形象，点击“付费下载 ¥N”，进入结算页，确认 N 个形象与金额，选择微信或支付宝，点击一次创建本次交易，付款成功后进入本批交付。

结算采用主内容加紧凑摘要布局，不重复两份作品列表。摘要包含名称、数量、合计，以及“返回修改”。右侧主操作用两项显式标签“直接支付”“群码免费”，替代下载方式下拉框。从首页进入时预选对应标签。

创建交易前可以修改选择和切换路线。创建后使用冻结的条目、价格与订单；若状态未确认，只允许“查询支付结果/继续本次支付”，不能通过切换标签获得新订单。尚未创建交易时切换路线不丢选择。

规则放在创建按钮附近一处：“本次支付仅用于这次下载。文件保存后可长期使用；以后重新发起下载需重新支付。” 不在每个区域重复。

#### 6.3 已选形象，群码免费领取

首页点击“群码免费领取”，结算页直接显示群码输入框。已验证且未过期时显示“群码有效，可免费领取本批”，无需重复输入。

未验证时只显示一个输入框和一个主动作“验证并免费领取 N 个”。内部先验证再创建批次，沿用现有两个接口，不让用户先点验证、再找第二个领取按钮。服务端验证成功但创建结果未知时，继续同一幂等请求，禁止重复创建批次。

输入去除首尾空格、字母统一大小写；仅接受 GD 加六位数字。错误显示在输入框下面，保留选择与输入。校验通过后不显示共享余额，因为这个码没有可扣余额。

没有码时点击“去粉丝群领码”，打开右侧面板，保留结算表单。面板内容仅为原始开发者抖音码、@山丘、抖音号 1872941388、复制按钮，以及“抖音扫码进入主页 → 加入粉丝群 → 查看置顶群码”。注明这是开发者主页码，不声称网站验证了关注关系。群码每三天更新说明放在此处。

侧面板不展示有效群码本身，不自动发布群消息。用户返回结算时，输入和所选形象仍在原位置。

### 8. 状态与失败恢复的固定行为

| 情况 | 用户看到的内容 | 下一步与保留内容 |
| --- | --- | --- |
| 群码格式不符 | “请输入 GD 和六位数字” | 保留输入与所选形象，在输入框修正 |
| 群码错误或更新 | 对应错误，不笼统说服务器故障 | 保留选择，可重新输码或在未建交易前切换支付 |
| 准备时间偏长 | “还在准备，你可以稍后刷新本批状态” | 使用同一批次；不自动新建 |
| 下载接口失败 | “本批文件暂未取得，请重试” | 保留交易和选择；重新取短时链接 |
| 下载被取消或未保存 | “请确认文件已保存”持续存在 | 同一批次重新下载，不重新支付 |
| 付款结果未确认 | “正在确认付款结果，请勿重复付款” | 查询原交易，不自动换订单 |
| 选中形象已下架 | 明确标出受影响的名称 | 保留其余选择；尚未创建交易时由用户移除 |
| 预览失败 | 固定预览区域内重试，仍显示名称价格 | 不闪烁整页、不清空卡片 |
| 没有当前交易 | 清楚说明没有进行中的交付 | 回图库；不新增历史找回功能 |
| 新建下载 | 重新显示本次价格或验证群码 | 本地已经保存的文件和客户端不受影响 |
