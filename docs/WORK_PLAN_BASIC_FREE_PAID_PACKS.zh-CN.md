## 1. 本轮目标

先用简单、可上线的产品验证真实选择：用户是否愿意直接使用免费的基础木鱼，是否愿意为扩展形象付费，是否愿意进抖音粉丝群领取码。

本轮不追求完整创作者生态，不继续完善共创，不重新打磨稳定的客户端。开发分两步：先完成业务功能修改；再沟通全新的官网 UI 方案，确认后实施界面重构。

## 2. 已确定的产品规则

| 项目 | 本轮规则 |
| --- | --- |
| 基础木鱼及客户端 | 始终直接免费下载，无需登录、进群、领取码或付款 |
| 扩展形象价格 | 每个 1 元，不设套餐、打包优惠或总价封顶 |
| 批次上限 | 每批最多 10 个不同的扩展形象 |
| 价格计算 | 1 个 1 元、3 个 3 元、10 个 10 元 |
| 付费含义 | 付款购买本次下载，不购买长期下载权益 |
| 再次下载 | 下次重新发起下载仍须付费，即使选择的是同一个形象；也可以使用当期有效的官方群领取码免费下载 |
| 已保存的文件 | 可长期离线使用，重新导入本地文件不收费 |
| 免费扩展领取 | 保留抖音粉丝群领取码路线，与付费路线并存 |
| 官方群码 | GD 加 6 位数字，不区分大小写，每七天更新一次 |
| 群码性质 | 权限凭证，不是兑换余额；正常领取不会扣减共享额度 |
| 图库位置 | 继续放在官网首页，不迁到独立页面 |
| 普通用户账号 | 不引入账号，不要求手机号登录 |
| 历史订单 | 不提供历史订单列表、订单查询、跨会话找回或历史免费重下入口 |
| 兼容范围 | 不做旧领取码、旧价格、旧权益和旧流程的兼容保护项目 |
| 共创 | 暂停开放新投稿及相关推广，不代表取消投稿功能；保留已有作品、账号、审核记录及后续恢复规划，不作为本轮上线条件 |
| GitHub | 说明和链接降为次要信息，不占据主要用户路线 |
| 客户端 | 保持纯本地运行，不校验付款状态，不加入线上账户或下载权限检查 |

服务端价格一律使用整数分：`unitPriceFen = 100`，`totalFen = 100 * distinctPackCount`。客户端提交金额不能作为收费依据。

基础木鱼不能被放入收费批次。扩展形象去重后须为 1 至 10 个；继续使用既有的文件体积限制和包格式，不把文件格式改造塞入本轮。

## 3. 一次性收费的具体边界

“一次性”指一次下载交易，不是买断，也不是终身下载资格。

| 场景 | 处理 |
| --- | --- |
| 当前页面已付款，准备文件暂时失败 | 允许当前交易重试交付，不再创建收费交易 |
| 同一次点击重复提交、支付通知重复送达 | 去重处理，不能重复收费或重复记账 |
| 当前交易已拿到文件 | 本次交付完成，不形成后续免费重下权益 |
| 以后重新进入官网，重新选择相同形象 | 新的下载交易，按当时单价重新付款，或使用有效官方群码 |
| 用户拿之前保存的文件再次导入 | 客户端直接本地导入，不收费、不联网验证 |
| 用户没有保存文件，之后想重新获取 | 重新付费下载或使用有效官方群码；不提供历史订单恢复 |

当前交易故障重试只服务于正在进行的交付，不做历史订单功能，不沿用旧的七天免费重下规则。服务端仍须保存支付处理所必需的交易标识、金额、支付结果、交付状态及去重信息；这不是用户历史订单功能，也不意味着建立长期下载权益。

本方案不要求删除真实交易底账、清空数据库或破坏支付通知去重。这些操作既不是简化用户流程所必需，也不在本次文档修订范围内。

## 4. 两条实际用户路线

### 4.1 基础体验路线

进入官网首页 → 了解桌面木鱼 → 免费下载对应系统客户端 → 安装并按系统提示授权 → 使用基础木鱼。

本路线没有领取码、付款或登录步骤。扩展形象购买失败不能影响基础客户端下载。

### 4.2 扩展形象路线

在首页图库预览 → 选择 1 至 10 个形象 → 选择付费下载或群码免费下载 → 获取一个批次文件 → 保存到本机 → 导入客户端。

付费路线：确认所选形象和总价 → 主动发起付款 → 服务端确认真实付款 → 准备文件 → 下载。

群码路线：已有码直接输入；没有码则查看开发者抖音码及进群提示 → 在群里取得当期领取码 → 回到当前选择继续领取 → 准备文件 → 下载。

切换两条路线不清空已选形象，不要求用户重复选包。不会核验用户是否关注抖音；持有有效群码即可领取，页面不能宣传为已验证关注身份。

## 5. 功能开发范围与顺序

### F1：收口共创与旧公开流程

- 隐藏官网公开的创作者入口、投稿宣传和作者推广码相关入口。
- 服务端停止新的公开创作者注册、投稿、上传、提交审核和作品更新，不只是隐藏按钮。
- 停止产生新的共创短信与 AI 审核任务；处理已在运行的任务时不粗暴终止其他服务。
- 后台保留现有形象管理、上下架和官方群码管理能力，不开发创作者结算、分成或贡献奖励。
- 本轮可下载图库只包含运营明确允许当前方式分发的形象，不自动把原共创作品转成收费商品。
- 不做作者码、旧领取码、旧权益或旧购买流程的兼容迁移，不以完善历史共创为上线前置条件。

退出共创不等于本轮批量销毁作品、账号或审核记录。是否删除资料属于另一个明确的清理动作，不自动混入发布。

### F2：恢复最小收费链路

- 只恢复扩展形象批次购买，不恢复捐赠、会员、套餐、长期权益或账户体系。
- 在服务端根据有效在架形象、去重数量计算 `100 * N` 分，拒绝空批次和超过 10 个的批次。
- 在创建交易时锁定所选形象版本及价格；交付不能临时换成别的版本。
- 沿用实际可用的既有支付渠道和通知校验代码，不因为代码存在就假定渠道已可用。
- 校验真实支付通知的签名、商户、交易和金额，前端“支付成功”提示不能直接换取文件。
- 支付创建和回调幂等；同一交易准备失败可以重试，新的下载请求不复用已完成交易作为免费权益。
- 付费和群码交付复用既有批次封装及签名能力，客户端不识别商品价格或支付方式。
- 支付渠道不可用时给明确错误，不伪装为已付款，不影响基础免费与有效群码路线。

### F3：保留官方群码免费路线

- 保留 GD 加 6 位数字的格式、大小写归一化及七天轮换。
- 后台显示当前有效码及其有效时间，方便复制到抖音粉丝群。
- 同一有效码可被多人使用，领取不扣减共享余额，不增加账号和额度钱包。
- 输入错误或过期时明确提示，保留所选形象并允许重新输入。
- 官网只展示抖音码和取得群码的方法，不能公开展示当前有效群码本身。
- 群码每批也最多 10 个，成功后交付一个文件，保存后可长期离线使用。

### F4：最小必要页面接线

此阶段不重构视觉布局，只让现有页面与新功能一致。

- 将所有对外价格统一为每个 1 元，删除套餐、封顶价、长期权益等冲突文案。
- 首页保留图库，接入所选数量、实际总价、付费下载和群码免费下载。
- 去掉历史订单及免费重下入口，不新建替代查询页。
- 在付款确认处明确：“本次付款仅用于本次下载。请保存文件；以后重新下载需再次付款，或使用有效群码。”
- 保留基本选择状态、错误提示和当前交易交付反馈，不建设新导航、新卡片体系或整套弹层。
- 基础木鱼继续直达免费下载，GitHub 降为页脚等次要位置。

### F5：功能收口后直接进入 UI 方案

本轮按用户最新要求不运行验收、测试、编译检查或桌面控制，不重复稳定的客户端计数、自启动、权限和签名测试。代理完成修改后直接汇总实现范围、已知限制和未验收状态，进入全新的 UI 用户旅程方案设计，不等待浏览器通道空闲。

部署状态单独记录，代码修改不等于已上线。UI 方案设计无需等验收或部署完成；UI 方案存在也不等于已获准实施界面重构。

## 7. 部署与数据边界

- 先确认当前代码、支付配置、发布范围和允许分发的形象，再做最小改动；不凭旧测试结果声称新价格链路已通过。
- 配置先就绪，再开放付费按钮；不得发布一个收款成功却无法交付的状态。
- 如需数据库变更，只增加当前交易所必需的字段和索引，不展开历史兼容或清库项目。
- 通过既有批准的服务器访问方式和持久 SSH 通道操作，只改牛马服务，不改桌球运行服务或外部部署工具。
- 如发生发布故障，先停止新增收费，并处理正在进行的已付款交付；不因回退产生第二次收费。
- 功能修改不要求重新签名或重新发布客户端安装包，签名事项仍由用户负责。
- 分别记录“开发完成”“验收通过”“生产部署完成”，不混用状态。

## 8. 最少的数据观察

| 观察项 | 用途 |
| --- | --- |
| 基础客户端下载按钮点击、服务端下载请求 | 看基础款是否吸引用户；不能当成实际安装人数 |
| 扩展图库选择及进入下载路线 | 看用户是否对扩展形象有兴趣 |
| 付费发起及服务端确认成功 | 看实际付费选择，而不是只统计付款按钮点击 |
| 群码成功领取 | 看免费群码路线使用情况；不能当成已验证的抖音新增粉丝 |
| 准备或下载失败 | 发现影响交付的问题 |

先利用现有日志和后台做必要统计，不新增庞大埋点平台、不采集键盘输入、不加入设备指纹。观察不是上线前额外等待周期，不预设流量或付费率门槛。

## 10. 分工和完成标准

建议实现时按清楚的目录边界并行：官网在 `website/`，交易与领取服务在 `services/gongde-payments/`，后台按既有实际目录负责群码与最小统计。先统一价格和交易接口，避免不同代理各自设计规则。产品负责人统筹范围与部署，不另建目标或检查点系统。

本目标功能完成标准：完成基础木鱼直接免费、共创入口与新增写入暂停、扩展每个 1 元且每次新下载重新付费、有效官方群码免费领取、每批最多 10 个及无历史订单功能的代码修改。明确标注未验收，不用测试或桌面控制作为收口前置条件。

本目标方案完成标准：功能修改后完成全新的桌面官网 UI 与用户旅程方案，给出布局、状态、文案及两条下载路线供沟通。确认后的 UI 重构与后续验收、正式发布属于下一执行阶段，不提前宣称完成。
