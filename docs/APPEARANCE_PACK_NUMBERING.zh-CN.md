# 统一形象编号功能设计

状态：设计已记录，尚未实现或上线。
来源：2026-10-05 用户要求，每一个形象包拥有通用编号，便于快速找到特定形象。

## 目标与编号规则

- 官方形象和创作者社区形象共用一个编号空间，不按作者、收费方式或栏目分开编号。
- 标准展示形式为 `GD-000123`，并明确标注“形象编号”。至少六位数字；超过六位自然延长，不截断、不回绕。
- 一个独立形象对应一个永久编号。同一作品更新文件或版本、改名、调整免费或付费状态、下架再上架，均不换号。
- 新的独立作品获得新号。编号不能手动修改，删除或下架后不回收给其他作品；出现跳号正常，不作为用户量或作品量宣传。
- 编号不包含账号、手机号、订单、审核记录或版本信息，不取代内部作品标识、版本标识及订单号。

## 分配与唯一权威

- 编号只由功德服务端分配，在本项目业务数据库内持久化；客户端和网页不得自行按列表位置生成编号。
- 采用全局原子分配与数据库唯一约束。官方与社区各自的作品身份映射到同一编号索引，约束“一个编号对应一个作品”“一个作品只有一个编号”。
- 索引只维护公开编号与现有作品身份的关系，不复制标题、价格、审核状态或版本等业务真相。公开代码是编号整数的规范格式，不另建第二份内容数据源。
- 已有作品进行一次幂等补号，使用既有稳定作品身份，不依赖名称或当前排序；同一任务重试不得重复分配。
- 投稿在服务端成功建立作品后分配编号，但编号存在不等于审核通过，也不等于可公开下载。

## 用户操作

- 官网官方形象和社区形象列表提供统一的“按编号找形象”入口。
- 输入 `GD-000123`、`000123` 或 `123` 都规范化为同一个精确编号；允许忽略前缀大小写和首尾空格，不做近似匹配或用标题猜测编号。
- 命中后直接定位该形象详情，显示名称、预览、作者、编号和当前实际可用操作。编号只解决查找，不改变官方付费、社区免费或现有订单权限。
- 未找到时明确提示“没有找到这个形象编号”，不重定向到其他相似形象。
- 已下架作品不展示不可下载的按钮；未公开投稿不可因知道编号而被匿名查询或预览，返回统一不可用结果，不泄露私稿资料。

## 展示与分享

- 形象卡片和详情页在名称附近用次级文字显示编号，提供“复制编号”和“复制形象链接”，不挤占购买或下载按钮。
- 创作者作品管理、审核列表和后台搜索均使用同一个编号；审核号和版本号另列，不能混写成形象编号。
- 客户端更换形象页展示已安装形象的编号，并支持按编号查找本机已导入的形象；未安装时可打开官网定位该编号，不自动收费或下载。
- 分享链接携带稳定作品编号，定位该作品当前公开版本。旧订单及既有下载凭证仍绑定当时的确切版本与摘要，不因分享链接定位新版本而改变。
- `.nmgpacks` 是包含多个独立形象的组合文件，不另给它一个“形象编号”；列表保留每个成员自己的编号，批次号和订单号保持独立。

## 交付与版本约束

- 不回写、重新签署或替换已经冻结的 `.nmgpack`、`.nmgpacks` 和历史交付文件。
- 若后续在新文件格式中携带编号，须同时更新相应签名覆盖与双端读取规则；不能通过修改现有签名文件补号。
- 本次仅添加设计，不修改正在验收的 0.8.4 冻结安装包及三份已授权原包。
- 实施顺序：服务端幂等编号和唯一约束，官网与后台精确查找及分享定位，再在后续客户端版本加入编号展示和本机查找。每一阶段分别报告实现、验证和上线状态。

## 验收条件

- 官方和社区作品不会重复编号；并发创建、补号重试和重复提交不产生第二个编号。
- 改名、换版、上下架及收费状态调整后，编号保持不变。
- 三种允许输入形式指向同一作品；不存在的编号不误命中。
- 匿名编号查询不能绕过审核、私稿、下架或下载权限控制，遵循现有公开查询限流。
- 官网、后台、创作者管理和支持此功能的客户端，对同一个作品显示同一个编号。
- 多包组合仍能逐一对应成员编号；既有官方付款、历史订单、授权签名和冻结文件字节保持不变。
