# 牛马电子功德产品体验优化工作方案

版本：1.0。日期：2026-10-11。状态：已于 2026-10-11 建立官方目标并开始实施；实际构建、验收及发布状态以根目录 WORK_PLAN.md 为准。

本方案把全面评估转成四批可独立交付的工作：性能与缓存、官网与共创流程、客户端可靠性、内容与运营。优先改善现有电脑用户的体验，不扩展支付、移动端或鸿蒙客户端。

当前业务规则仍以 `PRD_FREE_DOWNLOAD_AND_CO_CREATION.zh-CN.md` 和用户已确认的修订为准。本方案定义优化任务和验收标准，不取代 PRD，也不是新的目标登记或执行检查点。执行进度统一记录在根目录 `WORK_PLAN.md`。

## 一 目标和范围

### 本轮要达到的结果

1. 官网第一次打开能很快看见形象，再次打开不重复等待全部预览素材。
2. 网站更新后，新旧访问者获得匹配的页面与资源，不再出现修正已发布但老用户仍看旧布局的混乱。
3. 新用户知道如何安装、判断计数是否正常、领取并使用新形象。
4. 共创者能完成第一件作品，理解失败原因，顺利更新作品，并获得清楚的署名和传播反馈。
5. 运营者能找到当前领取码、观察真实领取情况、处理异常，而不需要理解内部技术编号。

产品的目的仍是用好用、有趣的免费桌面工具吸引关注和创作。下载请求、领取批次和新增抖音粉丝是不同指标，不能相互替代。

### 不变的业务规则

- 基础木鱼随客户端直接免费提供，无需账号、领取码、关注或进群。
- 官方与共创形象统一展示；扩展形象使用群码或作者码免费领取，不恢复付费、分成或钱包。
- 领取码为 GD 加六位数字，不区分 ASCII 字母大小写，保留前导零；每三天轮换，不恢复旧长码兼容。
- 群码每批最多 10 个；作者每件有效贡献增加 3 个批次名额，上限 10 个。领取不消耗次数，也不扣共享余额。
- 已保存的合规形象文件可永久离线使用；不恢复首次导入时限，不把服务器重新下载窗口混同为本地使用期限。
- 共创者继续手机号登录；不增加昵称必填、手工填写作品 ID 或消费者账号。
- 作者在外部工具制作并封装；平台负责校验、预览、审核、上架与分发，不建设在线 AI 绘图器。
- 保留版权和 AI 审核授权、格式安全检查、版本锁定及异常人工复核，不用流程简化削弱安全条件。
- 客户端继续离线，不采集输入内容、鼠标坐标、窗口内容或剪贴板，不增加联网遥测。
- 不恢复全屏自动隐藏，不开展手机适配，不重新上架用户已经指定下架的六个形象。

## 二 工作批次与发布顺序

| 批次 | 主要交付 | 依赖 | 发布安排 |
| --- | --- | --- | --- |
| R1 性能与缓存 | 入口缓存修正、公开预览衍生资源、受控并发与跨次缓存 | 当前公开作品及版本基线 | 可拆成 R1a 入口缓存、R1b 预览性能分别发布 |
| R2 官网与共创流程 | 页面层级、领取栏时机、领取反馈、制作修复提示与作品更新反馈 | R1 的资源接口与缓存约定冻结 | 官网和必要服务改动独立发布，不等待客户端 |
| R3 客户端可靠性 | 计数状态、自检、首次使用与导入结果、安装和升级说明 | 两端行为约定；各自真机验收条件 | Mac 与 Windows 分别通过才分别发布，不互相冒充通过 |
| R4 内容与运营 | 官方介绍、质量标准、署名分享、作者数据、运营异常总览 | 现有统计字段及公开作品数据 | 可先发布文案与署名，再发布后台增量 |

正式签名和公证作为独立事项并行准备。申请、审批和证书可用是不同状态；不能让外部审批拖住官网优化，也不能把申请提交写成签名问题已解决。

执行开始后先完成 R1a，R1b 与 R2 的不冲突工作可并行。客户端与内容工作使用独立路径推进，但主控同一时间只协调一次正式发布，避免混合候选和回滚边界。

不在本方案中承诺未经验证的总工期。以批次出结果，每批完成即交付，不等所有优化攒成一次大版本。

## 三 R1 性能与缓存

### W01 页面版本与缓存一致性

已知依据：评估时普通访问创作者页命中旧 HTML 和旧资源引用；仅在测试标签页绕过缓存后才得到新版工作台。需要修正的是版本到达用户的机制，不重新开发已完成的工作台布局。

主要位置：官网入口 HTML、资源引用与牛马站点专属响应头配置。共享部署基础设施仅通过既有受管入口操作，不顺带修改其他项目的缓存。

工作内容：

1. 实施前读取实际 HTML、JS、CSS、图片、接口的缓存响应头和浏览器命中情况，形成一张按资源类型分类的表，禁止全站统一设为不缓存。
2. 可变入口 HTML 采用每次访问有效重新校验的策略，例如 `Cache-Control: no-cache` 配合版本校验标识。
3. JS、CSS 和固定内容资源使用版本化地址；入口与引用资源一起发布。旧页面仍可能引用的旧资源保留至过渡与回滚窗口结束。
4. 发布检查增加已有缓存的浏览器正常访问，不只检查无缓存 HTTP 请求和服务器文件摘要。
5. 处理旧长缓存过渡：新的响应头不能主动清除已经存在的浏览器缓存。必要时由更新后的导航使用版本化入口地址，引导获得新页面；原书签仍可能受旧缓存期限影响，必须如实记录过渡边界。不能承诺修改响应头后所有旧标签页立即自动变新。

验收条件：新策略下正常返回页面得到当前版本；页面与脚本、样式不混用；升级前浏览器从更新后的导航可以到达新版；历史版本引用不产生 404；不要求用户把强制刷新作为日常使用步骤。

回滚方式：回到上一份冻结站点入口及其配套资源，保留旧资源可读，不批量清除与本项目无关的 CDN 或浏览器数据。

### W02 公开预览与安装素材分离

已知依据：一次观察中预览相关资源传输约 10.4 MB，最后一项在约 33.4 秒完成；重复打开等待约 20 秒时仍只有 7 个图库预览完成。实现存在页面级缓存、公开图片 `no-store` 和跨作品串行排队。

主要位置：`website/community-preview.js`、`website/free-flow.js`、`website/pack-player.js`；服务端创作者预览、对象存储与公共目录模块。安装用源包、签名和客户端格式不改动。

确定的实现方向：

1. 从已经审核通过的确切版本生成静态封面和网页专用动画预览素材。先显示封面，选择作品不等待动画图层全部就绪。
2. 预览使用适合实际显示尺寸的素材。缩放时同步处理预览坐标、旋转中心与完整动作包围盒；不修改安装素材字节，不重新签署原始包。
3. 衍生资源身份绑定审核版本、渲染器版本和输出规格；同一内容重复访问使用同一地址，内容变化才产生新地址。
4. 公开且版本固定的衍生图片允许长缓存；当前目录与领取资格仍及时校验。私有投稿、审核材料、带身份的接口响应不进入公开缓存。
5. 全页面素材请求使用最多 4 个并发任务，优先当前可见和悬停作品，其次下一行；不在打开首页时预载全部作品高清素材。
6. 保留鼠标移入或键盘聚焦自动播放。离开、页面隐藏或滚出视口时暂停，不清空已显示封面；尊重减少动态效果设置。
7. 先准备当前公开作品的衍生资源，再切换列表引用。新版本预览生成失败时不能展示残缺作品，也不能替换仍正常的旧公开版本。
8. 保留现有体积、解码与内存保护。衍生资源通过本项目已有受管存储和公开预览链路交付，不默认新增公有桶或放宽原始包权限。

建议采用的性能验收基准：电脑视口 1440×900，固定 20 Mbps 下行和约 80 ms RTT，使用同一浏览器与同一公开作品集合。基准是本轮工程验收条件，不宣称代表所有网络。

| 指标 | 本轮目标 |
| --- | --- |
| 首组 4 个封面 | 导航后 3 秒内可辨认、可选择 |
| 同版本正常重访 | 首组封面约 1 秒内恢复，不重复传输完整图片体 |
| 首组封面总体积 | 目标不超过 500 KiB；超出必须单列原因和处理结论 |
| 未进入图库 | 不预先拉取整个库的动画图层 |
| 滚动回来、筛选返回 | 已就绪预览不回退为整卡加载占位 |
| 作品下架 | 新目录和领取校验禁止新领，不把本地旧缓存解释为仍可领取 |

正式对比限定为相同条件下冷缓存和正常重访各 3 次，记录每次结果与中位数，不据此推算 P95。失败只重测受影响场景，不扩大成全站压测。资源预算例外不得默认为通过。

发布步骤：先上线兼容的新预览能力和资源，再切换前端使用；观察功能及失败情况后决定保留。回滚时恢复旧引用，不删除已冻结审核版本或旧安装素材。

## 四 R2 官网与共创流程

### W03 页面层级与可见操作

主要位置：`website/index.html`、`styles.css`、`free-flow.css`、`free-flow.js`、`app.js`。

- 首页主动作保持免费下载客户端，提供系统推荐但不限制切换；“挑选扩展形象”作为清楚的次动作。
- 没有选择且尚未进入图库时不显示固定领取栏；进入图库或已有选择时显示。离开图库但已有选择仍保留操作入口。
- 图库保留一个名称与编号搜索框及常用排序；标签、作者编号放入更多筛选，清除筛选不清空选择。
- 缩减图库标题、说明和共创邀请的前置高度；在 1440×900 下进入图库后能看见第一行完整形象主体与名称，领取栏不能遮挡必要操作。
- 统一卡片预览比例、名称、短编号、署名和选中反馈；编号和文字可复制，键盘可选择，不仅依赖颜色。
- 不重做品牌、不更换框架、不增加大段过场动画。继续使用现有纸色、墨色和橙色视觉。

验收采用 1440×900 和 1280×720 两个桌面视口；1024×600 仅检查关键按钮和表单可操作性。不做手机布局测试。

### W04 领取与下载反馈

主要位置：`website/claim.html`、`delivery.html`、`download.html`、`free-flow.js`；仅在确有接口缺口时修改服务。

- 沿用已经完成的就近取码、状态一致、数量差额提示和选择恢复，不另造一套领取状态系统。
- 普通用户统称“领取码”，验证后解释群码或作者码及每批上限；不展示内部 family、幂等标识或公式。
- 扫码离开、返回、码到期和请求失败后保留选择。提示用户下一步，不静默减少或替换作品。
- 处理中使用真实阶段，没有可信传输进度时不显示假百分比。
- 领取成功后突出下载文件与导入说明，浏览器只能确认请求发出时不声称已经安装成功。
- 保留同一领取批次的重试和恢复，避免用户重复点击生成多个批次。
- 下载页继续当前版本优先、历史版本折叠；补齐经核实的系统版本和架构范围，不能把没有测试的组合写成已支持。

必要回归包括：群码、作者码、小写和前导零、过期码、超过当前权限、返回后恢复、失败后重试。沿用既有记录和受控测试数据，不能为了测试而轮换真实群码或修改真实作者贡献。

### A01 制作指南与可修复错误

主要位置：`website/creator-guide.html`、`creator.html`、`creator.js`、`creator-community.css`、`docs/CREATOR_PACK_GUIDE.zh-CN.md`，以及现有指南打包入口和服务错误映射。

1. 用户只看见下载指南、外部制作、上传预览三个主要步骤。作品编号由平台生成，不要求作者处理内部标识。
2. 指南包含可直接交给外部 AI 的任务说明、标准模板、一个合格示例和视觉目标；明确外部工具必须能够生成并导出真实文件。
3. 把常见错误分成文件结构、图片格式、体积或画布、声明不完整、系统暂不可用。每类提供一条具体修复动作。
4. 提供“复制给制作工具的修复说明”，包含允许公开的技术问题和目标要求，不包含账号、手机号、令牌、恢复码或服务器内部路径。
5. 已有素材标准化能够安全完成的操作继续复用，不能为降低失败率接受脚本、任意文件或突破解码预算。
6. 明确区分正在编辑的版本与当前公开版本；更新被拒绝或待审时保留原公开版本，修正继续在原作品上完成。
7. 草稿、已上传、审核中、需要修正、系统重试和已公开均有清楚反馈；页面关闭后能恢复服务端已有进度，不伪造尚未保存的数据。

验收只需要一个已获授权的正常样本覆盖创建与更新，并用隔离的无害样本覆盖常见格式错误。非法或危险输入只在本地隔离校验，不向公开作品库或收费模型反复投送。

## 五 R3 客户端可靠性

### C01 计数状态与首次引导

主要位置：`src/macos/app.mm`、`src/windows/app.cpp`；共享行为由主控维护，两个平台分别实现。

在右键菜单或可达的状态面板中提供统一概念：全局计数正常、当前只能点击宠物计数、需要检查权限或监听状态。各平台只显示实际适用的原因，不照搬另一平台的权限措辞。

增加用户主动触发的短自检，提示切换到其他应用进行几次键鼠操作，分别判断监听是否收到事件、计数是否更新。自检只保留事件次数、状态和相对时间，不记录输入内容、鼠标坐标或窗口信息。

不能把“刚才没有输入事件”直接判为故障，也不能仅凭权限开关外观断定正常。Mac 延用实际事件监听状态判断；受系统安全输入等条件影响时明确说明范围，不绕过保护。

首次使用只介绍拖动、右键菜单和计数状态三件事。缺权限时给出清楚恢复入口，避免用户不知道功能处于降级状态；普通使用不频繁弹窗打扰。

验收必须包含常规安装路径与正常启动方式，在其他应用中进行真实输入。终端直接启动、合成键鼠事件或菜单可点击不能代替这一项。

### C02 导入结果与升级保护

主要位置：两端 `app` 与 `appearance_pack` 模块，安装脚本、版本资料和必要的安装说明。

- 单包成功后明确显示并启用该形象；批量成功后展示新导入列表并允许立即选择，不让“最后一项被启用”成为用户无法理解的隐式结果。
- 重复包、损坏包、部分失败、缺失文件分别给出简短结论；已正常使用的形象和累计数据不能因失败丢失。
- 更换形象窗口标出当前形象和本次新增项；导入后列表立即可见，无需重开软件才能发现。
- 保持应用身份、安装位置、用户数据和自启动设置稳定。新增客户端版本使用新版本号与独立产物，不覆盖已经发布的 0.9.1 文件。
- 保留当前计数口径、功德日历、离线运行和既有合规包兼容性；不借本轮重写整个客户端架构。

Mac 和 Windows 各自验证：首次启动、跨应用计数、单包与批量导入、切换、退出重开、升级保留数据。已验证且未改动的部分承接已有证据，不无差别重做所有历史测试。

Windows 不通过本机桌面控制叠加 UU 远程进行验收，避免重复此前的不稳定链路。代码、构建和本地可做的工作先推进；真机由用户或可信测试者按同一清单执行。未取得结果的 Windows 候选不得标成实机通过，可继续保留当前正式版本，不阻塞其他平台或官网。

### C03 正式签名和安全说明

准备 Mac Developer ID 与公证、Windows 适用分发方式的签名路径，核对账号资格、证书用途和真实成本。只记录凭据引用，不把密钥放进仓库、报告或候选包。

证书购买、身份认证或平台审批有外部依赖，单独记录具体状态。未获正式签名时继续如实显示安装限制；不保证签名后所有电脑都不会提示，也不引导用户关闭全局安全保护。

功能候选是否发布与签名事实分别写明。不可因等待证书把已经完成的官网优化长期扣住，也不可用开发签名冒充面向公众的正式公证交付。

## 六 R4 内容与运营

### A02 作者署名与分享

继续使用短作者编号和已有可选抖音号，不增加个人资料必填项。第一轮不建设复杂个人主页、排行榜或新的奖励货币。

- 卡片和可公开的作品信息保持明确署名；抖音号只展示作者已提供并获准公开的值。
- 使用现有图库承接作品分享，链接采用 `index.html?work=<作品通用编号>#characters`，打开后定位对应作品，不自动领取或替用户确认授权。
- 作品暂不可用时展示可理解的状态并允许浏览其他公开作品，不泄露私有草稿或拒审原因。
- 分享链接不携带领取码、手机号或会话。作者愿意分享自己的码时，可通过现有复制文案动作单独提供，并显示到期时间，避免把轮换码固化在永久链接中。
- 作者工作台展示确有数据的作品领取次数和近期变化，明确不是安装人数或独立用户数；缺失数据显示未统计，不显示伪造的零。

作者权限仍按当前贡献规则计算。本轮增加的是被看见与获得反馈的机会，不修改每件加 3、最多 10 的业务规则。

### O01 作品内容质量

为当前 13 件公开官方作品分别准备与真实动作相符的一句话介绍，保持现有名称、编号、作者和动作不变。不为了文案修改重签安装包，不绕过社区作者公开文字变更的审核流程。

制作一张轻量视觉验收表：实际尺寸可辨认、透明边缘干净、动作完整不裁切、浅色与深色背景可见、预览与安装后形象一致。安全审核通过不等于视觉质量自动通过。

后续以精选和主题征集鼓励质量，不以单纯上传数量刺激灌水。抖音作品展示可先人工运营，不在第一轮建设自动发视频系统。

### O02 运营异常与现有统计

主要位置：`admin-console/src/` 的免费领取、作者贡献和审核页面，以及现有统计与审核接口。先复用已有四类统计，不新建另一套报表数据库。

第一轮运营视图包括：当前群码及明确到期时间、可复制群公告、群码与作者码来源、领取准备失败、长时间等待的审核和审核预算提示。先提供能定位问题的入口，不追求复杂图表。

统计口径保持一致：首次就绪的批次只记一次；作品按对应批次条目计数；重新下载不增加作品领取次数；下载请求不等于安装成功；作者来源归因不因三天换码而丢失。

若现有数据不足，先显示未采集及其含义，再为必要指标补最小的服务端记录。不增加客户端联网，不读取用户输入，不用指纹或新增持久身份追踪猜测人数。新事件不得记录实际领取码或完整带参数 URL。

安装包管理增加当前引用与历史保留信息。对仍被官网、最低兼容要求或回滚流程引用的产物，不能只靠一条删除警告就直接移除；应先解除相应引用并满足保留条件。

## 七 并行协作与修改边界

方案阶段不新建子任务。开始实施后按模块安排，最多同时推进 3 条实质开发线，减少合并与沟通成本。

| 角色 | 独占主要范围 | 不得越界 |
| --- | --- | --- |
| 主控 | 本方案、现有执行记录、接口约定、共享版本文件、候选整合和正式发布 | 不把子任务口头完成当作发布或验收通过 |
| 官网前端 | `website/` 的预览、图库、领取与创作交互 | 不自行修改业务权限、源包格式、生产配置 |
| 服务与后台 | `services/gongde-payments/src/creators/`、必要的公共目录与免费统计模块、`admin-console/src/` | 不修改收费、分成或无关订单逻辑，不擅改 IAM |
| Mac 客户端 | `src/macos/` 及主控明确分配的 Mac 构建文件 | 不重置用户数据或批量重签已有安装包 |
| Windows 客户端 | `src/windows/` 及主控明确分配的 Windows 安装文件 | 不开启 UU 远控，不把 CI 运行冒充用户真机 |

这是一组可分配角色，不要求同时启动全部人员。第一轮以前端、服务和主控为主；客户端工作进入对应批次后再分配。验收由主控使用新视角按清单完成，必要时增加只读验收角色，不让多个代理争抢同一个浏览器或本机桌面。

每个子任务开工前取得精确文件白名单。共享类型、版本模板、同一个 HTML 或样式文件只分配一个写入者。交付包含修改清单、明确完成项、实际验收结果和未解决条件，不追加无关重构。

## 八 有限但完整的验收

按变更选择必需场景，已有有效结果可在确认边界未变后承接，不为完成报告重复创建账号、作品或领取批次。

| 场景 | 关键结果 | 证据边界 |
| --- | --- | --- |
| 普通用户首次访问与回访 | 封面快速出现，旧缓存能按计划迁移，新页面资源一致 | Ego 桌面实测，不代替原生安装 |
| 浏览与选择 | 悬停动作、筛选保留、返回不闪空、数量上限正确 | 使用既有公开作品 |
| 群码与作者码领取 | 权限不同但都不扣次数；重试不重复生成批次 | 优先复用已获授权数据；真实新领数量保持最少 |
| 文件交付 | 文件可下载，既有批次可恢复，过期提示真实 | 下载成功不等于客户端导入成功 |
| 作者新作与更新 | 自动编号、错误可修复、版本分离、授权不被自动勾选 | 只用已确认授权样本；真实送审不以 Mock 替代 |
| Mac 日常使用 | 常规启动下跨应用计数、导入、更换、重开正常 | 实际输入与真实客户端结果 |
| Windows 日常使用 | 中文安装、跨应用计数、导入、更换、重开正常 | 独立真机结果；没有结果就保留待验收 |
| 运营处理 | 当前码、到期、来源、异常和历史数据口径正确 | 后台页面与服务真实数据，缺数不伪造 |

影响哪一层就验证哪一层，不把前端改字扩展成整个数据库和所有平台重测。测试工具有缺陷时先判断是否影响产品结论；无法得到可靠结论则修最小问题或换用直接人工检查，不开展独立的测试框架完善工程。

每个实际失败保留证据，确定原因后进行一次有针对性的修复和复测。若复测仍失败，先更新因果判断，再决定下一步，禁止不断重试相同路径。

## 九 发布与回滚规则

1. 开始实施时读取现有访问文档与最新执行检查点，绑定实际发布基线。使用批准的 SSH 别名、受管发布入口和持久连接，不因目录整理或连接已存在扩大权限。
2. 同一候选只包含本批白名单内的变更，保留当前发布文件、素材和历史兼容登记。不能重新打包未修改客户端冒充新版本。
3. 官网、API、后台、Mac、Windows 分别记录版本、摘要、实际生效位置和验收状态；允许分批发布，不要求所有组件同时变化。
4. 预览资源先就绪，再切换可变引用；不得把用户引向尚未生成的文件。新增服务行为优先保持对旧页面兼容。
5. 有状态变更确实不可避免时，单列前向和恢复方案；不得为本轮优化删除历史订单、改写贡献或清空领取记录。
6. 发布后只做本批关键路径检查；如出现加载错误、版本混用、领取回归或数据损坏风险，回滚该组件，不盲目反复发布。
7. 发布成功、网页可用、原生验收、签名审批分别记录。不能用其中一个状态替代其他状态。

不对每个普通实现细节重复征求意见。确有不可替代的身份认证、真实付款、缺失的素材授权或超出范围的共享基础设施变更时，集中说明具体需求；其他不受影响的工作继续推进，不全线等待。

## 十 鸿蒙与本轮之外的事项

鸿蒙电脑只列为后续机会，不进入本轮开发验收，也不购买设备或创建第三套发布流水线。运行 Windows 的华为电脑继续使用 Windows 版。

重新评估的条件为：出现明确的鸿蒙电脑用户需求，有可用真机，且确认正式分发条件下的跨应用输入监听、桌宠窗口和后台运行能力适用。满足后只做基础木鱼原型，再决定是否移植完整形象体系；不能用只在自身窗口响应点击的版本冒充同等功能。

移动端、完整国际化、在线 AI 制作器、社交动态流、排行榜、支付与分成、全屏自动隐藏都不进入本轮。后续需求应说明替代或推迟哪项工作，避免优化任务持续膨胀。
